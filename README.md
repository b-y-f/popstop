# 啪停 PopStop · MVP

手机优先的静态网页：在浏览器本地监听袋装微波爆米花的爆裂声，并在爆裂节奏变慢时提示用户亲自停止微波炉。

## 暂定名称

**啪停 PopStop** — 中文直观表达“听到啪声、提醒停下”，英文名简短、便于 GitHub Pages 项目名和未来品牌延展。这个名称仅为产品暂定名；发布或商业化前应另行做商标与域名检索。

## MVP 做了什么

- 手机端优先的单页体验；不需要后端、构建工具或账号。
- 通过 Web Audio API 在设备本地建立环境噪声基线，识别短促、宽频的声学突发。
- 使用可测试的阶段状态机：须先在两个连续时间窗内确认密集爆裂，再确认回落并结合“距上次爆裂”的间隔提示低焦糊风险的停机窗口；开头零星爆裂不会解锁提醒。
- 提供“少焦糊 / 平衡 / 多爆一些”三个偏好，以及“太早 / 刚好 / 太晚”本机反馈校准。
- 带有演示模式，可不使用微波炉预览交互。
- 不录音、不上传音频、不控制微波炉。

## 部署到 GitHub Pages

1. 新建一个 GitHub 仓库，例如 `popstop`。
2. 将本目录中的 `index.html`、`styles.css` 和 `app.js` 上传到仓库根目录并提交。
3. 在 GitHub 仓库中打开 **Settings → Pages**。
4. 在 **Build and deployment** 选择 **Deploy from a branch**，分支选择 `main`，文件夹选择 `/(root)`，然后保存。
5. 等待 GitHub 给出页面地址；在手机上通过该 `https://` 地址打开。

> 浏览器只会在 HTTPS（如 GitHub Pages）下允许网页申请麦克风。不要用手机文件管理器直接双击 `index.html` 测试听音功能。

## 使用提示与边界

- 手机放在微波炉外、干燥稳定的台面，建议离炉门约 0.5–1 米；不要放在微波炉上或靠近热气。
- 开始监听后，前两秒用于建立环境噪声基线。尽量关闭音乐、减少谈话和餐具碰撞。
- 这是辅助提醒 MVP，不是自动断电器，也不承诺唯一“完美秒数”。品牌、玉米含水量、微波炉功率和厨房噪音都会影响判断。
- 请始终在微波炉旁，看到提示后由用户亲自停止，并以气味、包装说明及实际情况为准。

## 下一步验证建议

用固定计时和人耳“爆声间隔”规则作为对照，在不同品牌、微波炉功率及安静/嘈杂厨房中记录：焦糊率、未爆粒比例、过早提醒率、提醒时间误差，以及用户反馈后的变化。这样才能判断通用模型是否真的优于简单规则。

## 判定保护逻辑

停机提醒只会在以下顺序成立时出现：

1. 监听到至少 7 个候选爆裂，且相邻两个 4 秒时间窗内各至少有 3 个候选爆裂；
2. 在已确认活跃后，爆裂率相对本轮峰值下降，或接近所选静默间隔；
3. 减速信号连续维持至少约 0.35 秒；
4. 距最后一次候选爆裂达到用户偏好的 1.7 / 2.1 / 2.5 秒阈值。

这不是对“每一声都一定是爆米花”的保证；它主要防止开头一两声或零散噪声直接触发提醒。核心时序逻辑在 `popping-logic.js`，可通过 `node tests/popping-logic.test.js` 验证两声、短促噪声团、正常回落与恢复爆裂等情景。
